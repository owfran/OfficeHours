How a login becomes a cookie the browser sends back:

Login is controlled by the login() funtion which redirects if the user is already logged in (current _user is true).
Otherwise the user has to input a user and password which it checks agains the database and adds them to current_user if correct.
Flask uses g for temporary local storage and g.session_token = create_session(user_id) triggers @app.after_request.
The function inside after_request checks if g.get("session_token"):, which is true after g.session_token = create_session(user_id).
response.set_cookie seems to to create a hold_session cookie that the function then returns.

The difference between the public board and a booking detail:

The public board/slots shows all of the open slots to any logged in user. 
Bookings is a user specific join that renders at /mine.html and only a user can see their own bookings (except mabey ta's)
-----------------------------------------------------------------------------
Which actions change server state (book, cancel, transfer, logout)

All those actions change the server state. Anything that changes the database changes the server state. book, cancel, transfer 
all effect the slots ad bookings tables. Logout changes the session table and so would login.

What the device-handoff link on My bookings is doing

The link lets you open your bookings page from any browser or device.
It uses a sid to allow you to view your bookings without being logged in. Probably contains a security defect

How I fixed it

This part was kind of hard to find a good solution for. Personally I think the most secure option would have been to get rid of the whole 
device handoff link entirely. But to preserve its function and dd security I had to do a couple of things:
app.before_request no longer does  token = request.args.get("sid") or request.cookies.get("hold_session")
and instead does token = request.cookies.get("hold_session")
This makes it so the sid does not authenticate the browser on any page of the site.
Next in app.get("/me"), I removed the check for @login_required and instead grabs the sid if available and returns a tmp_user that
is used in a duplicate logic of the normal /me page.
This way the sid logic is isolated to only work on the /me page and does nothing on any other page, which is more secure because
nothing on the /me page can change the system state.
It also didn't copy the ta's logic because I am assuming that a ta should be logged in to view their bookings regardless, which might
have been a creative freedom by me.
